# Linuxサービス追加点検・修正

2026-11-12（Asia/Tokyo）。前回報告の4件と周辺の追加問題を現行作業ツリーで修正した。既存の未コミット変更は保持した。

## 前回報告の4件

| 問題 | 修正 |
|---|---|
| tmpfilesのx除外が清掃に反映されない | 設定全体からx/Xを集め、globと階層を考慮して清掃に適用。xは配下も保持、Xはディレクトリ自体を保持し内容は清掃する |
| r!等が通常実行でも削除する | !エントリを解析段階で除外し、作成・削除・清掃すべてに--boot条件を適用 |
| RuntimeDirectory等が配置先外へ作用する | 5種類のディレクトリ指示を事前検証し、絶対パス・親への遡行・空の名前を拒否。全階層をO_DIRECTORY/O_NOFOLLOWで開き、FDに対してchmod/chownする |
| f+が既存内容を更新しない | 通常のfとf+を分け、f+は検証したFDを切り詰めて内容を置換する |

## 追加で修正した問題

- 不正な清掃期限が0秒扱いになり、即時削除する場合があった。全体を厳密に解析し、不正値・未知の単位・無限値は清掃せずエラーにする。
- 権限が「-」の既存ファイル・ディレクトリを、既定の0644/0755へ変更していた。既存のmodeを保持し、新規作成時だけ既定値を使う。
- 通常の日本語文字列もunicode_escapeで復号し文字化けしていた。バックスラッシュのエスケープ部分だけを復号する。
- 前回修正後もwのFDをabモードで包むため、通常のwまで追記になっていた。wは先頭から書き込み、w+だけ追記する。
- 同じファイルへの複数のw+行を重複として除外していた。すべての追記行を適用する。
- 抑止されたboot限定行が、後続の同じ種類・パスの通常行まで重複扱いで抑止していた。重複判定前にboot条件を適用する。
- eのglob指定が属性変更だけに適用され、清掃では動いていなかった。清掃も展開後の対象ごとに実行する。
- 親の清掃が子に明示された別の清掃設定を無視していた。子の清掃境界で親の走査を止め、子は自身の期限に従う。「-」なら保持する。
- コピー先がコピー元配下だと、再帰的に自己コピーして異常終了・大量作成する。作成前に拒否する。
- 存在しない所有者・グループを黙って無視していた。作成・書き込み前に検証しエラーにする。

## 互換性と範囲

リンクを介したサービス用ディレクトリの属性変更、不正なディレクトリ名・期限・未解決のアカウント指定はエラーになる。清掃を安全側へ倒すため、これまで黙って動いていた設定が拒否される場合がある。

対象はサービス管理・tmpfilesと前回修正の周辺。プロジェクト全体の完全監査や、同一UIDのプロセスに対する完全な隔離を意味しない。
